# ZERITH 独立采集工作台

网站默认运行在 **8090**。项目、进程、页面和数据索引均独立于 `/home/robot/control`，不会调用 8080 API，也不会初始化机器人或发送关节运动指令。

## 启动

```bash
/home/robot/collection_web/start.sh
```

已安装用户服务：

```bash
systemctl --user status zerith-collection-web.service
systemctl --user restart zerith-collection-web.service
journalctl --user -u zerith-collection-web.service -n 50
```

默认监听 `0.0.0.0:8090`。浏览器访问 `http://机器人IP:8090`。页面更改刷新生效，Python 更改需要重启；不要在采集中重启。

## 采集操作

1. 结束 Apifox 的采集调用。连接 Meta Quest，并按厂商遥操作流程初始化机器人。
2. 在页面最上方输入场景编号并点击“应用”，创建或选择 `日期_scene编号` 目录。填写 Prompt；网站提取左右物体，可手动修正。高度标签可选，仅记录到每条 episode，不参与目录命名。设置阶段数，展开“采集参数”设置频率和最长时长。
3. 点击“设备检测”，全部通过后点击“启动采集”。配置通过厂商 `MetaTransfer` 提交；以厂商生成的任务元数据确认接受。
4. 用 Meta Quest 控制每条数据的开始、分阶段、结束。页面显示当前阶段、帧数、录制时长及保存状态。
5. 完整保存后自动编号为 `episode_000001` 等，默认评级 A；可改 B/F、查看三路视频、或确认放弃并删除该条数据。
6. 先用手柄结束当前录制并等待保存，然后点击“结束会话”关闭网站持有的采集连接。关闭网页不会自动关闭后端会话。

所有新保存的 episode 默认评级 A，由采集者在记录列表中点击 A/B/F 即时修改。时序检查结果只记录在检查详情和 timing_quality.json，不自动改变评级，也不限制人工选择 A。人工评级写入 review.json 和网站索引，刷新或重启后保留。序号删除后不复用；只有网站本次会话新生成的数据会自动整理，启动前已有数据不自动改名。

电量百分比只作显示，网站不再因低于 20% 阻止采集；电量状态未知仍提示检查失败。原厂设备保护不受此设置影响。

## 独立依赖

- 厂商 gRPC `127.0.0.1:50051`：任务配置、VR/设备状态、相机预览。
- 厂商状态服务 `127.0.0.1:25120`：电机错误、通信、电量、初始化和控制模式。
- 厂商 ZCM `ipcshm`：只读订阅 `waist_state`、`head_state`，明确对应电机 2—6；不构造占用固定 UDP 端口的机器人控制客户端。
- H1 1.3.9 相机 SDK、Python 3.10、grpcio/protobuf/h5py/numpy/opencv-python，以及 g++/pkg-config/zcm。
- `.venv` 使用本机 zerith Python 的系统包；Playwright 只用于开发测试，不是网站运行依赖。

`joint_observer.cpp` 只封装公开状态订阅接口，没有任何控制消息发布。`start.sh` 在源码更新或二进制缺失时编译。

## 权限与文件

Web 服务以 robot 用户运行。厂商 root 写入的新数据需要继承 ACL：

```bash
sudo setfacl -m u:robot:rwx,d:u:robot:rwx /data/zerith_data
```

已有任务目录若不可写，应对**该任务目录**设置相同 ACL，之后创建的 episode 会继承权限。网站启动前会检查目录可写性。无需把 Web 服务以 root 启动，也无需把 sudo 密码写入任何脚本。

- `runtime/collection.sqlite3`：会话、编号、评级、操作记录；不要删除，否则无法保留历史编号映射。
- `runtime/session_*.json`：任务配置快照。
- `runtime/meta_*.jsonl`：厂商响应记录。
- `episode_XXXXXX/review.json`：原 UUID、序号、评级与人工复核标志。

保留 HDF5 原始 episode_id 和采集日志；改的是目录名称。现有训练转换器不会自动读取 review.json，后续可按该文件或网站索引筛选 A/B/F。

仅对明确完成、结构检查通过的文件做自动整理。未完成/异常的文件留在原目录供检查。关闭会话后不再接管后续由其他客户端产生的数据。断线不自动重新提交 MetaTransfer，避免重复任务。

## 按日期与场景命名目录（2026-09-14）

页面最上方提供采集日期编号（默认北京时间当天 YYYYMMDD）、场景编号（正整数）和“应用”按钮。点击应用立即创建或选择目录，不需要先填写提示词，也不启动采集。例如场景 1：

```text
/data/zerith_data/20260914_scene1/episode_000001
/data/zerith_data/20260914_scene1/episode_000002
/data/zerith_data/20260914_scene2/episode_000001
```

最终目录只由日期编号和场景编号决定，提示词、左右商品、高度标签均不参与。相同日期和场景下，不同商品、不同提示词以及不同会话共用连续 episode 编号。切换到其他场景独立编号，切回来继续递增；删除后不复用，服务重启后仍保留编号。

每条 episode 的 `collection_task.json` 保存该条真实 `config.task_name`（提示词）、`config.scene_id`、采集参数、左右商品、高度标签及路径；厂商 HDF5 内原有提示词和 UUID 保留。场景根目录不写入某个商品的通用 task_meta.json，避免多提示词场景产生歧义。历史目录及其元数据不追溯改写。

“应用”结果保存在 `runtime/selected_scene.json`，刷新或重启后可恢复。修改输入框后必须再点应用才能启动；会话期间锁定场景设置，结束会话后可切换。空闲页面跨天更新默认日期后，需要重新应用，运行中的会话保持原目录。

接口：`POST /api/scene/apply` 接收 `task_id`、`scene_id`，返回已创建的 `dataset`；不依赖提示词或机器人服务。`POST /api/task/directory` 仍为只读任务校验，返回最终目录及原厂暂存路径。启动请求必须对应服务器最近应用的日期与场景。

兼容原厂采集：厂商仍按原任务配置写入 `编号_提示词` 暂存目录。网站只在一条完整保存、校验通过后移动到场景目录并编号，不搬动正在写入的数据。结束会话后只清理本次空暂存目录及匹配的 task_meta.json，原任务说明保存在 runtime；有未完成数据、未知文件或符号链接时保留。历史数据不自动迁移。

## 遥操提示与固定升降柱（1.0）

配合 `/home/robot/teleop_zero_lock` 扩展，页面显示标定成功、遥操状态和头腰偏差预警，可启用当前浏览器语音提示。头腰位置偏差不再暂停遥操；原厂故障保护仍保留。

“固定升降柱”支持 0–0.8 m，反初始化后保存，下次初始化平滑到位并保持。它与任务区记录到 episode 的高度标签分开；此设置不改 Prompt 或采集文件内容。配置通过 `POST /api/teleop/config` 原子保存，不直接发送电机命令。关闭固定后，下次初始化恢复厂商升降柱遥操逻辑。


## 按目录查看采集记录

采集记录按保存目录聚合，同一目录跨会话的记录合并显示。当前目录默认展开并显示全部已登记 episode，其他目录默认仅显示名称和条数，展开后才读取该目录明细。轮询保留手动展开状态；切换当前目录后重新默认仅展开当前目录。空闲时以已应用的场景目录为当前目录，采集中以实际会话目录为准。顶部“本批已完成”和评级汇总也按目录统计。

`GET /api/episode-groups` 返回轻量目录汇总，`GET /api/episodes?dataset=...` 按目录读取完整索引，不受旧全局列表 1000 条限制；历史视频按记录 ID 查询。范围为网站已登记的记录，未导入的外部数据目录不自动纳入索引。

2026-09-09 验证：目录跨会话分组和筛选、已有评级/删除/视频接口测试通过；浏览器验证当前目录 9 条记录（8 条已完成）、3 个历史目录默认折叠、明细按需加载、展开状态保留、视频预览、手机布局无整页横向溢出。截图与结果位于 research/directory_groups_20260909。


## 分阶段采集

任务区直接显示“采集阶段数”，新会话默认 2；不会因上次已结束会话是 1 阶段而把默认值恢复为 1。运行中保留实际会话阶段数并禁止修改；结束会话后重置为 2。原 `subtask_num` 原样经网站验证传给厂商，`step_list=[]`，原生 Y 键逻辑未改动：长按超过 2 秒开始本条，松开后短按一次 Y 完成当前阶段，累计完成指定阶段数时结束并保存。

默认两阶段：第一阶段按 Y 进入第二阶段，第二阶段再按 Y 结束本条。阶段卡显示操作提示和当前进度；保存记录显示实际已完成/总阶段数。历史任务、episode 和目录元数据不追溯改写。

2026-09-09 检查确认此前网站恢复的历史会话配置为 subtask_num=1，而后端默认原本为 2。此次修正默认恢复与可见性；浏览器拦截提交验证默认发送 2，并用模拟状态验证阶段 1→2→保存提示，没有启动真实录制或发送机器人动作。

## 紧凑界面与人工评级（2026-09-14）

场景、日期与目录合并为顶栏，任务及设备状态并排显示，关节详情与更多参数默认折叠。采集记录的 A/B/F 按钮位于编号旁；每条保存完成后可立即评级，即使下一条正在录制，也可修改之前已保存数据的等级。检查提示默认折叠，历史评级不批量覆盖。

前端使用 `GET /api/status?compact=1` 获取当前录制与计数，不重复传输整批历史记录。目录明细在汇总变化、正在录制、用户评级或 15 秒兜底刷新时获取；未变化的列表复用，不在每次状态轮询时重复请求。

验证：60 项单元和 HTTP 测试，以及 browser_compact.py、browser_timing.py、browser_scene_directory.py。覆盖时序异常默认 A、人工 A/B/F 保存及重启恢复、采集会话中的评级、其他页面修改同步、未变化列表不重复拉取、场景流程和手机布局。

### 2026-09-15：录像回放与保留统计

8090 回放通过 `GET /api/review/{id}` 获取各相机的可用状态，再通过支持 Range / HEAD / ETag 的视频接口读取。按采集 UUID 查找录像，支持同一批次内重命名、批次改名和 `raw_data` 归档；优先使用原批次和原始归档，多份无法确定的录像会明确报错。查找仅建立内存索引，不修改采集记录的编号、路径或原文件。

回放窗口提供三路统一播放、暂停、拖动、倍速和重新加载，关闭窗口释放旧视频请求；某一路失败显示原因，其他可用画面仍可播放。回放期间暂停页面实时相机图片轮询，减少带宽竞争。

目录统计使用 `retained`（排除 `deleted` / `deleting`）；`total` 仍保留全量历史记录数。已保存数量和 A/B/F 数量继续只计算 `completed`。列表、原 episode 编号和下一条编号规则不变。

验证：`.venv/bin/python -m unittest discover -s tests -p 'test_*.py'`；真实 H.264 浏览器回归为 `tests/browser_video_review.py`，使用文件开头 `REAL` 指定的三路录像副本、临时数据库，不向机器人提交采集任务。
