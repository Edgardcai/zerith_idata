# GPT-6 Astra 与质检完成判定（20260921.1）

默认模型改为 `gpt-6-astra`，继续使用部署方已有 API 文件中的地址与 key，通过 Responses API 调用，`store=false`。设置页可选择 GPT-6 Astra，也保留 GPT-5.6 Terra。Astra 使用 `low` 推理强度；请求输出预算至少 8192 token，包含推理所需空间。证据编号通过 JSON Schema 枚举约束生成，并继续按每条数据/每只手核验，错误证据不能成为通过结果。

每台服务器的质检进程仍共用一个请求名额，排队锁在进程退出时自动释放。429、并发已满、408、500/502/503/504、连接中断和超时默认持续等待后重试，直到接口恢复或用户停止任务；等待时日志持续更新。遵循 Retry-After（30～3600 秒），无此信息时等待30、60、120秒，后续120秒。不再因为次数用完将临时限流记录交付为已质检。三台服务器的本地队列独立，共享 API key 的跨机限制由网关反馈后各自等待。

401/403、无效配置、额度不足等不可自动恢复的问题明确保留未完成状态。模型返回缺项、错误证据等，批量动作复核最多自动补查两轮，只重查失败记录，复用成功缓存。若仍失败，不标记整批完成；处理错误后再次增量质检会补查未完成记录。

HDF5 报告将接口失败显示为“未完成”，不伪造 A/B/F 自动质检等级、不计入“已质检”数量。人工等级与备注保持独立。CLI 批次有任何未完成记录时返回非零退出码，汇总中明确给出失败数量。

自动质检流水线仅在整组记录全部处于已通过/已拒绝终态后才导出。存在待复核、未完成、排队等待的记录时，不发布本轮部分导出。自动任务可暂停、继续；没有三次限流后放弃的上限。已经完成的有效结果可以复用。

手动的“直接转换 LeRobot”“直接切分左右手”继续按用户之前设定直接执行，不增加必须先质检的条件。这里的完成要求适用于明确执行的质检任务及其自动导出。

模型配置仅影响新任务或明确重试的任务，不改写已保存的人工判断。旧模型的报告和缓存保留；模型或检查策略变化时，新的自动检查按当前策略产生结果。
