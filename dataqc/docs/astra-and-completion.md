# GPT-6 Astra 与质检完成判定（20260921.1）

默认模型改为 `gpt-6-astra`，继续使用部署方已有 API 文件中的地址与 key，通过 Responses API 调用，`store=false`。设置页可选择 GPT-6 Astra，也保留 GPT-5.6 Terra。Astra 使用 `low` 推理强度；请求输出预算至少 8192 token，包含推理所需空间。证据编号通过 JSON Schema 枚举约束生成，并继续按每条数据/每只手核验，错误证据不能成为通过结果。

本机请求队列自 20260930 起使用跨进程 FIFO 队列及可配置请求槽位，默认 `api_concurrency=2`、批次线程数 2。槽位在进程退出时由系统释放；被终止的排队者自动清理。排队、接口调用及每次重试耗时分别记录在批次目录的 `request-timing.jsonl`，不记录密钥或请求头。

请求启用 Responses SSE 流式接收（`api_stream=true`），保留完整的结构化结果校验。只有终态事件返回完整 response 后才处理结果；断流、未完成输出不得成为成功缓存。`api_timeout=90` 是连接以外的 HTTPX 网络空闲超时，连接超时仍为 10 秒。流事件读取时同时检查 `api_progress_timeout=90` 秒的有效输出空闲时间，以及 `api_request_deadline=300` 秒的单次请求总预算；心跳不视为生成进展，正常持续输出可以超过 120 秒。到时关闭流并按连接异常重试。JSON 响应网关仍兼容。

连接中断、超时和 408/5xx 的重试退避为 2、4、8、15 秒；重试等待期间释放请求槽位。429/账户并发已满对本机所有调用统一冷却，无 Retry-After 时等待 30、60、120 秒，后续 120 秒；有效 Retry-After 按 1～3600 秒处理。明确的 gateway_concurrency_limit 另外将本机暂时降为单路至少 300 秒。默认仍持续等待直至恢复或停止，未完成的请求不会交付为已质检。三台服务器的队列独立，共享账户的跨机限制仍以网关反馈为准。

批量输入将共用的 evidence 字段无损提取到 evidence_defaults，同一证据编号按默认字段递归合并、逐条字段覆盖。保留所有数值精度、状态、阈值与证据编号，未减少检查。原始完整证据及已验证结果的签名保持兼容，可以复用历史成功缓存。运行日志逐批报告已完成条数，正式汇总仍在整组检查结束后生成。

401/403、无效配置、额度不足等不可自动恢复的问题明确保留未完成状态。模型返回缺项、错误证据等，批量动作复核最多自动补查两轮，只重查失败记录，复用成功缓存。若仍失败，不标记整批完成；处理错误后再次增量质检会补查未完成记录。

HDF5 报告将接口失败显示为“未完成”，不伪造 A/B/F 自动质检等级、不计入“已质检”数量。人工等级与备注保持独立。CLI 批次有任何未完成记录时返回非零退出码，汇总中明确给出失败数量。

自动质检流水线仅在整组记录全部处于已通过/已拒绝终态后才导出。存在待复核、未完成、排队等待的记录时，不发布本轮部分导出。自动任务可暂停、继续；没有三次限流后放弃的上限。已经完成的有效结果可以复用。

手动的“直接转换 LeRobot”“直接切分左右手”继续按用户之前设定直接执行，不增加必须先质检的条件。这里的完成要求适用于明确执行的质检任务及其自动导出。

模型配置仅影响新任务或明确重试的任务，不改写已保存的人工判断。旧模型的报告和缓存保留；模型或检查策略变化时，新的自动检查按当前策略产生结果。

待复核的 B 保留具体判级原因，不再统一覆盖为“按当前规则为 B”。历史 F 因规则调整降为 B 时，显示调整说明、已取消硬失败的检查名称及历史原因。此显示兼容不会修改原始报告或人工等级。
