# 等级冲突优先级

用户于 2026-09-12 明确指定，后续修改必须保持：

**人工复核等级 > VLM／自动质检后等级 > 采集原始记录等级。**

- 按等级来源确定优先级，不是按 A/B/C/F 字母决定谁覆盖谁。
- 人工复核 F、VLM A、采集 A，采用 F；人工 A、VLM B、采集 F，采用 A。
- 没有人工复核，采用已给出的自动质检等级；没有自动等级，显示采集等级。待复核标记独立保留，无人工确认的待复核数据仍不提前导出。
- 刷新页面、重启、重新质检和新的 VLM 结果都不能清除已保存的人工等级。逐条人工再次保存才能更新该人工结论。
- “全部采用质检后等级／全部采用采集等级”是显式人工批量选择，但跳过已经逐条人工复核的记录。批量选择的记录允许再次批量切换；来源保存在 `selected_from`，不修改原始采集与 QC 结论。
- 人工等级绑定 episode 稳定标识；新报告会更新并发编辑版本并使旧导出批准失效，但不使人工等级失效。需要导出时根据当前数据重新检查转换条件，数值完整性与转换验证保持现有规则，检查失败不把人工等级改成自动等级。

实现：`integrations/replay_grades.py`（状态、保存、回放、批量采用）、`pipeline_web_app.py:authoritative_quality_grade_entries`（转换采用等级），`tests/test_grade_choices.py`、`tests/test_unified.py`。

此规则替代旧验收文档中“新报告使人工选择失效”的描述。
