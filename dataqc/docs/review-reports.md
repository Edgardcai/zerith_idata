# 逐条任务参考与质检报告

规则版本 `zerith_qc_6`。数据集目录仅用于定位，不声明商品、操作手或升降高度。

- 真机任务读取 HDF5 `task_name`；缺失时读取本条 `collection_task.json` 的 `config.task_name`，再尝试 `episode_meta.json` 的 `task`。原始任务不被改写。句末有无英文句号均能解析。
- 仿真任务读取 `meta/episode_meta.json` 的 `task/prompt`，与左右手目标及阶段记录核对。
- 升降高度优先读取本条元数据的 `targets.lift_height`（单位 m）；支持明确的 `target_lift_height`、`lift_target_height` 字段。多个已提供目标冲突、非有限数值或格式无效时保留待复核，不因目录缺少后缀判 F。
- 无独立目标时使用该条首帧 Action 的升降指令检查高度保持。报告明确说明这种检查不能证明独立任务目标已达成。状态与指令容差仍为 ±0.02 m。
- 派生副本通过来源记录回溯原始 episode 的参考值。不同 episode 不共享目录推断值。

主报告表显示关键异常和问题总数。“全部问题”默认按失败、待复核、预警排序；“全部检查”包含正常项、无法验证项和执行状态。每项显示实际值、标准、来源和已记录的全部异常位置，可逐处跳转回放，并下载完整 JSON。旧报告未保存的位置明确保留缺失，不编造帧号。

时间间隔逐处列出；腰头分通道列出均值与 P1/P99；升降柱分别列出状态和指令范围、最大偏差与超差帧数；夹爪列出每手实际及要求次数。重复的整体 State 跳变与左右臂跳变合并展示。视频完整性、画面质量、阶段和提示词异常独立保留。

Terra 数值复核与图像类别识别分开。无法从轨迹确认掉落、碰撞、物理抓取或任务成功时显示“无法判断”，不等同于发现异常。已记录的缓存命中显示“复用有效历史结果”。

旧规则报告保留原等级并提示重新质检，不自动重新跑用户数据。人工等级优先于质检等级，质检等级优先于采集等级；问题清单不因人工改级被删除。

比较模块的任务类型从提示词读取，商品仍需属于既定列表。比较中的时间/帧率判定和抽样范围沿用原实现；这次没有将比较模块等同于完整 HDF5 视频质检。
